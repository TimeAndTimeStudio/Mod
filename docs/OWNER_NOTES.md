# Notes สำหรับเจ้าของเซิร์ฟเวอร์

## ค่าที่ต้องตั้งใน `config/claimmap/claimmap.properties`

| คีย์ | ค่าแนะนำ / หมายเหตุ |
|---|---|
| `bindAddress` | `0.0.0.0` — ถ้าเป็น `127.0.0.1` เครื่องอื่นจะเข้าเว็บไม่ได้ (ม็อดจะ log เตือน แต่ไม่เขียนทับ) |
| `players` | รายชื่อที่อนุญาต คั่นด้วย `,` (ว่าง = ไม่จำกัด) |
| `admins` | รายชื่อแอดมิน คั่นด้วย `,` |
| `startingBalance` | เงินเริ่มต้นผู้เล่นใหม่ |
| `sellPercent` / `buyPercent` | ต้อง `sellPercent < buyPercent`; ค่าผิดจะถูกตีกลับเป็น 70/130 |
| `blockedItems` | ไอเท็มที่ห้ามซื้อ/ขาย/ประมูล |
| `pricesUrl` / `pricesAccessKey` | JSONBin — **ห้าม commit คีย์** |
| `auction*`, `shop*`, `mailboxMaxEntries` | ปรับตามต้องการ |

หลังแก้ `players`/`admins`/ราคา ใช้ `POST /api/admin/config/reload` ได้ แต่ `port`/`bindAddress` ต้องรีสตาร์ท

## ความปลอดภัย

- **HTTP ไม่เข้ารหัส** — ใช้ใน LAN/VPN เท่านั้น รหัสและ session วิ่งเป็นข้อความเปล่า
- **offline-mode** — ใครสวมชื่อคนอื่นเข้าเกมได้ ระบบล็อกอินในเกมจึงสำคัญมาก
- `token` (master token) ใช้ได้เฉพาะ `POST /api/command` จากสคริปต์ ห้ามใส่ในหน้าเว็บหรือส่งให้ผู้เล่น
- **คีย์ JSONBin เดิมเคยอยู่ในไฟล์ HTML สาธารณะ** → ควรหมุนเป็นคีย์ read-only ใหม่ และเก็บเฉพาะใน config ของม็อด
- `reset-password` แล้ว ผู้เล่นต้องเข้าเกมและตั้งรหัสในหน้าต่างที่ขึ้นให้ทันที — ระหว่างนั้นใครสวมชื่อนั้นก่อนจะตั้งรหัสได้ ควรแจ้งเจ้าของชื่อทันที

## การอัปเกรดจากข้อมูลเก่า

- ตอนสตาร์ทครั้งแรกหลังอัปเดต ม็อดจะคัดลอกไฟล์เดิมทั้งหมดไป `config/claimmap/backups/pre-upgrade-<เวลา>/` ให้อัตโนมัติ (ครั้งเดียว)
- `claimmap.properties` เดิม: คีย์ใหม่ถูกเติมค่าตั้งต้น แต่ **ไม่เขียนทับค่าที่เจ้าของตั้งไว้** รวมถึง `bindAddress=127.0.0.1`
- `accounts.json` รูปแบบเก่า (SHA-256 หรือยังไม่มี uuid) อ่านได้ทันที ผู้เล่นเดิมใช้รหัสเดิมได้ และระบบจะอัปเกรดเป็น PBKDF2 ให้เมื่อล็อกอินสำเร็จ
- บัญชีเก่าที่ยังไม่มี uuid จะถูกผูกกับ UUID ตอนผู้เล่นเข้าเกมครั้งแรกหลังอัปเดต
- `sessions.json`, `regions.json` ไม่ถูกแก้หรือลบ

## หน้าต่างล็อกอินตอนเข้าเกม

- ใช้ dialog ของเกมในช่วง **configuration** ก่อนเข้าโลก ผู้เล่นไม่ต้องลงม็อดฝั่งไคลเอนต์
- ถ้าปิดหน้าต่าง/กด Esc/ส่งแพ็กเก็ตปลอม ระบบจะกันไม่ให้เข้าโลกและแสดงหน้าต่างใหม่ (หรือตัดการเชื่อมต่อเมื่อผิด 3 ครั้ง/เกิน 60 วินาที)

## สำรอง / กู้คืน

- ระบบสำรองทุก 1 ชั่วโมงไปที่ `config/claimmap/backups/<yyyyMMdd-HHmmss>/` เก็บ 24 ชุดล่าสุด และสำรองอีกครั้งตอนปิดเซิร์ฟเวอร์
- **คัดลอกโฟลเดอร์ `backups/` ออกไปเครื่องอื่นเป็นระยะ** เพราะถ้าดิสก์ลูกเดียวพังจะหายทั้งหมด
- วิธีกู้คืน:
  1. หยุดเซิร์ฟเวอร์
  2. คัดลอกไฟล์จาก backup (`economy.json`, `ledger.jsonl`, `accounts.json`, `mailbox.json`, `auctions.json`) กลับไปที่ `config/claimmap/`
  3. ตรวจความถูกต้อง: `java tools/CheckLedger.java config/claimmap` ต้อง PASS
  4. เปิดเซิร์ฟเวอร์
- `ledger.jsonl` คือความจริงสูงสุด — อย่าแก้มือ ถ้าจำเป็นต้องแก้ให้แก้ทั้ง ledger และ snapshot ให้สอดคล้องกัน

## เมื่อตลาดถูกปิด (503 `market_disabled`)

แปลว่าไฟล์เงิน/ของ/ประมูลอ่านไม่ได้ ระบบจะเปลี่ยนชื่อไฟล์เป็น `<ชื่อ>.corrupt-<epochMs>` และ **ไม่สร้างไฟล์ว่างทับ**

1. หยุดเซิร์ฟเวอร์
2. ดู log ระดับ SEVERE ว่าไฟล์ไหนเสีย
3. กู้ไฟล์นั้นจาก `backups/` หรือแก้ไฟล์ให้ถูกต้อง
4. ห้ามลบไฟล์ `.corrupt-*` ทิ้งจนกว่าจะกู้เสร็จ — ใช้เป็นหลักฐานได้
5. เปิดเซิร์ฟเวอร์และรัน `CheckLedger`

## Master token / สคริปต์

`POST /api/command` รับเฉพาะ master token (admin session ธรรมดาไม่ได้) และรันคำสั่งบน server thread เหมาะกับสคริปต์ผู้ดูแลเท่านั้น

## Build

```
./gradlew build
./gradlew build -Pminecraft_version=26.2 -Pfabric_api_version=0.161.0+26.2
```

ต้องผ่านทั้งสองเวอร์ชันก่อน deploy

## ข้อจำกัดที่รู้อยู่

- การรับของจากกล่องอาจซ้ำ 1 stack ถ้าเซิร์ฟเวอร์ดับในมิลลิวินาทีระหว่างให้ของกับบันทึกไฟล์ (เลือกให้ซ้ำดีกว่าของหาย)
- การเปลี่ยนชื่อ Minecraft (online-mode) อยู่นอกขอบเขต — บัญชี/เงินผูก UUID แต่ whitelist/ล็อกอินเว็บผูกชื่อ
- หน้าเว็บไม่มีไอคอนไอเท็ม PNG; แสดงชื่อแทน
- ประมูลจะ settle ตอน tick แรกหลังมีคนเข้าเกม ถ้าเซิร์ฟเวอร์ว่างจน pause
